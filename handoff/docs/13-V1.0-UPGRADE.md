# 从 V1.0.0 升级到 V1.1.0

## 1. 当前结论

用户已选定EnglishMahjong-web牌桌UI。新包是完整替换交接基线；已经实现的规则引擎、网络、身份和存档可以继续使用，不因换UI重建业务。新项目直接用V1.1.0开始。

| 旧内容 | 本次处理 |
|---|---|
| 白蓝椭圆桌、浅色背景、首版不使用真正3D | 已废止，由木边绿绒/深棕环境/真实Three.js牌桌取代 |
| 原六项玩法、状态机、牌库、游戏契约、91条验收 | 保持原语义与文件内容 |
| 原UI组件与Socket adapter | 可复用无视觉耦合部分；新增TableViewAdapter和统一手牌控制器 |
| 三份提示词、执行计划、模型交接、决策记录 | 全部按新UI采用路线更新 |
| Mac+火山云Caddy/frp部署模板 | 保持；新增客户端GPU/资源与故障处理要求 |
| UI验收只有布局/交互 | 增加源码采用、真实WebGL、材质/相机对照、字体/容量/故障恢复 |

## 2. 已经开始开发时的安全顺序

1. 记录当前分支、commit、未提交修改、原验证结果。保留用户工作，建立可回退的独立变更分支或等价检查点；不要覆盖整个已有项目。
2. 将新包放入handoff位置。旧包可作为只读历史归档，但任务入口和提示词只指向当前版本，不能同时执行冲突视觉要求。
3. 保留packages/engine、server、contracts的已验证逻辑。逐项比对本包不变量；只有实际差异才改代码。
4. 按docs/11建立源码采用记录，完成M0-V四人真实3D基线。现有UI可在迁移分支暂留作回退，不把临时旧UI作为最终验收。
5. 用新显示adapter接已有公共/本人私密投影，先跑2/4/6人，再补3/5与所有mySeat排列。确认本人的视觉旋转不会改变上/下家。
6. 迁移排句、逗号、圈词、倒计时、连接状态。保留唯一草稿与命令入口；不同时启用旧手牌按钮和新mesh动作。
7. 执行原91条受影响项及新UI验收，保留未受影响且仍有效的验证证据。最终全人数/恢复/公网环境项仍按完成门处理。

## 3. 新增接口不改变游戏协议

`contracts/table-view.ts`是显示边界。它从原`types.ts`的公共快照和本人私密快照派生，不允许显示层新增可裁决的规则。若已有代码使用别的schema，先写明确字段mapper与类型检查，禁止将整个`ServerOnly.RoomAggregate`传给前端以“省映射”。

新UI的显示revision/generation、摄像机状态、纹理缓存键只在客户端有意义；它们不能替代server stateVersion/phaseId/controlEpoch。线上原规则版本无需因为换材质而增加。

## 4. 本包与未来实现分开

此包附上游原始文件快照、哈希、许可、图与适配规范，供Codex实施。它不包含已经完成的文字麻将服务器，也不声称上游切片可以独立npm启动。最终项目在自己的源码目录中采用/改造文件，并保留来源和版权；references快照保持原样。

完成后由Astra审查同视口原图与真实WebGL新图，以及规则/恢复证据。仅更新README里的版本号不算迁移完成。
