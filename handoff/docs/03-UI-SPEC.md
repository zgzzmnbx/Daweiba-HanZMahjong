# Astra 界面与交互规格 · V1.1.0 · EnglishMahjong 牌桌

本文件供 Astra 规划和实现界面。权威语义以 `01-RULES.md` 为准；Sol 负责真实状态和命令校验。视觉参考位于 `../ui-reference/reference.html`，可直接本地打开。参考只展示设计，不代表联机功能已实现。

视觉参考暂用“字间｜文字麻将”作展示名称，仅是可替换的命名建议，不属于用户确认的规则或固定品牌要求。

## 1. 已选定的视觉基线

用户于本轮明确选择 [EnglishMahjong](https://englishmahjong.com) 的牌桌 UI。实现必须采用 [Bruce-pac/EnglishMahjong-web](https://github.com/Bruce-pac/EnglishMahjong-web) 的真实 Three.js 牌桌渲染路线。固定研究基线是提交 `6830301df3061cdd25350cf56807473e5505b311`，逐文件采用范围和素材许可见 [11-ENGLISH-TABLE-ADOPTION.md](11-ENGLISH-TABLE-ADOPTION.md)。本规格取代 V1.0 的白蓝椭圆桌方案；游戏规则仍以 `01-RULES.md` 为准。

### 1.1 必须保留的视觉识别

- **真实三维桌面**：深棕暖暗环境、木质厚边、绿色绒面、前大后小的透视构图。牌桌是主画面，不做成后台卡片网格。
- **真实立体麻将牌**：奶白牌面、轻微圆角与倒角、暖金色牌背、可见厚度和贴地接触阴影。以汉字纹理替换英语牌面。
- **围坐关系**：本人在近侧，其他席位围绕远侧与两侧；4 人场景应能与上游原图直接对照。5/6 人扩展仍保持同一种木边绿绒桌，不换成蓝白椭圆图案。
- **反馈颜色**：金色 `#FFD24A` 表示本人选中/当前行动；青色 `#4FD1FF` 表示新摸牌/恢复信息；反对选区用浅赭红 `#EC9B80`。颜色同时有文本/形状反馈。
- **私密排句优先**：前沿的 14 个汉字始终清楚。透视不承担逗号索引和投票句子语义。

姓名、房间号、人物都是演示数据。`字间｜文字麻将` 仍是可替换的显示名。上游截图中的三个人物模型不属于本次必须复用的桌体 UI；素材来源未明确时使用同等布局空间的中性昵称头像，不复制第三方人物模型。

### 1.2 真实 3D 与 DOM 的分工

| 模式 | 本人手牌可见层 | 输入层 | 对局桌面 |
|---|---|---|---|
| `DESKTOP_TABLE` 默认 | Three.js 中的真实立体手牌 | 与投影同步的 DOM 命中/辅助技术层，经唯一 `SentenceRackController` | 真实 Three.js |
| `DESKTOP_COMPOSE` 整理句子 | DOM 排句区；同一批本人 3D 手牌隐藏 | 同一控制器接收 DOM 拖拽/点击/键盘 | 保留 Three.js，减少背景动效 |
| `MOBILE_PORTRAIT` | 固定 DOM 两行手牌，本人 3D 手牌隐藏 | 同一控制器 | 上方保留 Three.js 牌桌 |
| `WEBGL_FALLBACK` | DOM 排句区 | 同一控制器 | 与原风格一致的可操作 2D 桌面回退 |

这些是展示模式，不是新增游戏阶段。显示模式不得修改 `PublicPhase.kind`、牌权、投票、倒计时或服务端 `stateVersion`。`WEBGL_FALLBACK` 仅用于 WebGL 不可用、上下文丢失或用户主动低性能模式，不得成为首版默认交付而跳过三维采用。

所有模式共享唯一 `orderedTileIds + commaAfterTileIds` 草稿和选中 tileId。切换时不能追加牌、丢牌、自动申胡、额外出牌或改变候选草稿版本。`HU_COMPOSE` 默认展开 DOM 排句区；`HU_VOTE` 用公开冻结句子的 DOM 面板，可读性优先。

桌面默认模式的 3D mesh 只展示牌面并参与屏幕投影计算，不装独立的命中监听，也不直接发游戏命令。所有命中意图由 DOM 输入层送给唯一 `SentenceRackController`。DOM 命中层使用 Three.js 相机计算出的屏幕四边形/包围盒；画布 `getBoundingClientRect()`、DPR、CSS 缩放、投影矩阵、camera epoch 与显示模式共同决定坐标。DOM 命中层必须与当帧 renderer revision 同步；如果失配，先禁用该命中帧并刷新投影，不能用上一帧位置选到相邻牌。拖动过程中锁定相机/缩放；松开或取消后再恢复。3D 可见牌与 DOM 可见牌不能同时形成两套可点击实体。

## 1.3 上游事实与本项目新增的区别

上游 `src/table3d/main-view.ts` 使用 `WORLD_SIZE=222`、3:2 画布、FOV 30 的透视相机，透视位置为 `(0,-WORLD_SIZE*1.44,WORLD_SIZE*1.05)`，X 旋转约 `π*0.3`；这些是本次读到的源码事实。本项目默认启用透视（上游同时支持正交），并增加按人数与可用区域调整的相机模板。数字是实现起点，不能宣称在所有设备已经得到合适取景或帧率。

## 3. 布局与人数适配

### 3.1 座次、世界坐标和视觉坐标分开

服务端 `seatIndex` 永远是 `0..N-1`。本人视角下 `r=(seatIndex-mySeat+N)%N`；`r=1` 为下家，`r=N-1` 为上家，2 人时同一人同时标注“上家 / 下家”。吃牌权限取服务端 `legalActions`，不能根据画面左侧/右侧或固定 `seat % 4` 推断。

以下为**本项目布局初值**，非上游已有 6 人实现。用桌心 `(111,111)` 为原点参考，标准化 `x/y` 经内桌半宽 90 转换为本地世界坐标：`worldX=111+90*x`、`worldY=111+90*y`。Z 朝上；本人 `r=0` 位于 y 负侧。表内旋转是从本人朝向绕 Z 正向的度数，决定对手牌背与弃牌区朝向；字牌行内的逻辑顺序仍由 tileId 数组决定。

| 人数 | 按 r=0…N-1 的 `(x,y,旋转°)` 初始锚点 | 全员在线胡牌门槛 |
|---|---|---|
| 2 | `(0,-.92,0)`；`(0,.92,180)` | 1/1 |
| 3 | `(0,-.92,0)`；`(.80,.58,126)`；`(-.80,.58,234)` | 2/2 |
| 4 | `(0,-.92,0)`；`(.92,0,90)`；`(0,.92,180)`；`(-.92,0,270)` | 2/3 |
| 5 | `(0,-.92,0)`；`(.90,-.36,68)`；`(.64,.84,143)`；`(-.64,.84,217)`；`(-.90,-.36,292)` | 3/4 |
| 6 | `(0,-.92,0)`；`(.88,-.48,61)`；`(.88,.48,119)`；`(0,.92,180)`；`(-.88,.48,241)`；`(-.88,-.48,299)` | 3/5 |

模板基于本人相对序号生成渲染位置，而非把所有人数写成原来的 `seat*90°`。视觉转向与所有权必须解耦；从任意 mySeat 看同一真实座次，都应保持下家→…→上家的同一循环。3 人和 5 人使用上述显式模板，不能误以为所有模板都是 `r*360/N`。

自己的牌按原上游约 `1.21875` 倍前沿比例起步；对手只显示背面及公开牌数，5/6 人时先缩小对手牌背（建议初值 0.70 倍）、错开两侧区域，禁止缩小自己的汉字来硬塞。物理牌墙是无字背面实例，可按余牌数量更新；视觉实例并不是隐秘牌序。物理牌视图容量覆盖本项目最多 216 张，拖动 ghost 与借牌引用另留至少 2 个位置或使用可增长集合；总视图容量至少 218，不保留源项目 108 的硬上限，也不能静默裁掉超限项。

### 3.2 相机与桌面 1440×1000

- 四人模式先复现原上游桌体、近侧大牌、两侧牌背、中央显示盘的构图，再扩展人数。默认透视 FOV 30。本人视角固定近侧；只提供受限“看牌桌/整理句子”取景，不开放绕桌窥看对手的自由轨道。
- 场景视口保留源项目 3:2 相机取景原则，在独立 `TableViewport` 内 fit；HTML 顶栏和底部动作条不强行拉伸 canvas。画布留边与房间暖暗背景一致，不能拉伸桌子。
- 5/6 人初始相机距离放大约 1.08–1.12 倍，保持 FOV；用投影包围盒校验木桌、自己的手牌和主动作均在安全区，再定最终参数。HUD 位置经过模板处理，不能落到字体最密集的牌面上。
- 自己 14 张手牌约 64×86 CSS px、汉字 38 px 的投影目标；低于 28 px 时自动切换 DOM 排句模式并保留三维桌。14 张应完整可见，禁止只显示其中一半再横向滚动。
- 木框可以轻微倒角、桌布低强度纹理、牌底接触阴影；材质避免高反光造成白牌过曝。中央显示盘改为“第几局 / 余牌数 / 当前行动倒计时”，不显示不属于本项目规则的东西南北积分、英语单词得分或英文字母序号。
- 主要按钮和逗号操作的可点击范围至少 44×44 px。正常回合显示出牌/申请胡牌；弃牌响应窗口才显示合法的吃/胡/过。

### 3.3 手机 390×844 与 430×932

竖屏是必验收布局，保留上半部三维桌面，下半部 DOM 排句。禁止要求用户旋转才能开始、投票或恢复身份。上方完整区域约 300 px，可用 390×260 的 3:2 canvas 加外部座位 HUD；430 宽按相同比例适配，页面高度不足时只让辅助说明滚动，不将主手牌裁掉。

390 宽的手牌布局明确为：**17 px 左边距 + 7×44 px 牌宽 + 6×8 px 间距 + 17 px 右边距 = 390 px**，牌面为 44×58 px。430 宽为 **20 + 7×48 + 6×9 + 20 = 430 px**，牌面为 48×62 px。两行最多各 7 张，汉字至少 28 px；尺寸与 `contracts/table-view.ts` 的 `MOBILE_RACK_METRICS` 保持一致。逗号是定位在左字末尾的 overlay 标记，**不能再把最多 3 枚逗号按普通 grid 列计宽**，否则第 7 字溢出。

- 行末逗号仍锚定该行末字，标记显示于该字右下角/行间，不能移成下一行首字的前置标点；跨行重排后以 tileId 锚重新计算。
- 逗号小标记本身可低于 44 px，但必须同时有“点逗号→点左字→放在后面”的 44 px 等价操作。拖拽吸附到逻辑间隙，不要求精准点中 8 px。
- 牌组每行固定 7 张，三逗号同时存在时仍必须通过 390 px 无溢出验收。安全区使用 `env(safe-area-inset-bottom)`；主要按钮至少 52 px 高。
- 对手头像最少保留昵称、牌数、上下家和在线/缓冲/AI文本。画面不能通过看到牌背后的汉字或完整牌墙 DTO 泄露信息。
- 投票句子采用同一 7+7 布局，支持跨行、跨逗号圈选。反对按钮完整显示“写的什么玩意”。

## 4. 私人排句区

### 4.1 排列

保留用户现有排列。新摸牌置于末尾并高亮；本局排序不根据拼音或词频自动重排。每张牌由tileId区分，同字多牌有各自实体身份。不得用汉字字符串作为React列表key。

显示“13字”或“14字”，但不把用户误导成已通过语义判断。吃来的牌本次不能打回，标注“刚接入”；出牌按钮禁用时给出确切原因。

### 4.2 逗号托盘

托盘固定展示三枚可操作的中文逗号，标明“已用x/3”。逗号不是麻将牌，不计入14张。

拖动逗号时，只有合法间隙出现可落点提示。13字有12个合法间隙，14字有13个；句首、句末和已被占用的间隙不可放置。拖回托盘撤销该逗号。

状态提交采用 `orderedTileIds + commaAfterTileIds`。逗号跟随其左侧牌ID，重排后若该牌变成末尾，逗号回托盘；被出掉的牌也会使其锚定逗号回托盘。UI即时解释一次，例如“逗号已回到托盘”。

窄屏间隙可以只画10—12px的逗号，但不能要求用户精确点击10px区域：提供“点逗号→选左字→放在后面”的44px等价操作。拖动落点按最近合法间隙吸附，跨两行时清晰提示将插到哪一字之后。

### 4.3 键盘和辅助技术

| 任务 | 键盘路径 |
|---|---|
| 选择字牌 | Tab进入牌组，方向键移动焦点 |
| 改变顺序 | Space拾起，方向键移动，Enter放下，Esc取消 |
| 放逗号 | 聚焦逗号按Enter，选择左字，Enter确认放在后面 |
| 撤逗号 | 聚焦已放逗号按Delete或操作菜单“移回托盘” |
| 出牌 | 选中字牌后聚焦“出牌”再确认；不以单键直接弃牌 |
| 异议圈选 | 方向键到首字，Space起选，Shift+方向键扩展，Enter确定一段 |

每张牌的朗读名可为“第7张，我”；逗号可为“位于后字之后的逗号，可移回托盘”。倒计时不每秒打断读屏，仅在阶段变化、剩余10秒时播报一次。遵循系统减少动态效果的设置。

## 5. 弃牌响应与胡牌排句

最新弃牌在桌面中央放大，标明出牌人、剩余8秒。只有服务端允许的下一家显示可用“吃”；其他人只可胡或过。UI不能根据点击顺序宣布抢到。

“胡”在此先登记意向。轮到自己的候选后，显示13张自有牌和1张标注“借用弃牌”的候选牌，提供45秒整理。提交前不公开排列。借用牌不代表已吃入，失败时不能把它保留在手牌。

候选排队时展示“已登记，等待前一位评审”，不能展示其他候选人的隐藏句子，也不能允许用户等待别人亮牌后新登记。

自有14张申胡直接提交当前排列和逗号；服务器格式拒绝时留在原阶段，显示具体修复信息。

## 6. 胡牌评审与圈选异议

### 6.1 层级

面板上方显示“阿白申请胡牌”“14字全用”“还剩36秒”。下面是冻结句子，必须由牌ID映射得到。其下显示“需3票赞成 · 已有2/5人提交”；绝不在投票中显示赞成数、反对数或谁投了什么。

主操作文案准确为“意思成立”和“写的什么玩意”。不把反对按钮改成“拒绝”“语义不通过”等其他文案。

### 6.2 圈选方式

“觉得哪里不合理？可圈选后再投反对票，也可以直接反对。”支持0—3个不重叠连续区间。鼠标拖过字牌选区，触摸先点起字再点止字，再次点已有选区可移除。

输入模型为0based半开索引 `[start,endExclusive)`，范围0..14；逗号不占索引，可跨逗号。按当前候选的固定顺序解释，重复汉字按位置分开。示例“我想把月亮装进你的口袋里带走”中，“月亮”为[3,5)，“口袋里”为[9,12)。示例仅用于展示选区，不代表这些表达应该被否决。

新增选区与已有段重叠时先合并为连续段；合并后最多3段。用户点击“意思成立”时清除本地异议选区，并只提交APPROVE，不把残留选区混进请求。点击反对按钮可直接发送REJECT与当前合法选区，提交后锁定。

### 6.3 投票身份与匿名性

仅冻结评审集合成员显示可用按钮。申请人显示“等待朋友评审”；AI和不在本轮集合的回归者显示“本轮无需投票”。投票者掉线不减少分母；返回的原评审只要没截止仍能投。

结算后展示赞成/反对/未投三项计数及门槛，以mergedObjectionRanges匿名合并高亮被质疑的片段，不显示每字被圈选次数。不能在公共状态里保留“玩家→反对区间”的映射。两人局的身份可被自然推知，UI不应宣传绝对不可识别。

## 7. 掉线与恢复体验

| 服务端事实 | 其他玩家看到 | 本人恢复后看到 |
|---|---|---|
| 缓冲15秒 | “可可重新连接中 · 12秒” | “已恢复原座位”，手牌和排列复原 |
| 缓冲后BOT | “可可 · AI托管”，辅助说明“只摸牌、出牌” | “已接回操作”，合法AI动作已保留 |
| 本人正常回合超时 | “本次超时代出” | 继续真人模式，不写成掉线 |
| 申请人评审时掉线 | 评审暂停，显示其恢复缓冲倒计时 | 及时返回继续；过期则申请已撤回 |
| 所有真人离线 | 本局暂停保存 | 返回后续局，展示暂停期间没有推进牌山 |
| 服务恢复 | “正在恢复牌局” | 快照完成后才允许操作 |
| 同席位在另一设备恢复 | 旧页面“已在其他设备恢复” | 新页面为唯一有效控制端 |

断线提示不得遮挡整副手牌，也不能用全屏报错打断其他仍正常进行的回合。只有规则明确暂停的阶段才全桌遮罩。

恢复入口应始终可发现：同浏览器自动恢复；首页“恢复原座位”输入私密恢复码。恢复码仅本人可见，可复制、重新生成；不要出现在邀请链接、房间号旁、公开截图或日志中。

## 9. 组件边界与真实数据接入

推荐组件：RoomLobby、TableViewport、EnglishTableRenderer、SeatLayoutTemplate、PlayerSeat、TurnStatus、DiscardFocus、SentenceRackController、ProjectedHandHitLayer、SentenceRack、HanTile、CommaTray、ActionBar、HuComposer、HuReview、ObjectionSelector、RoundResult、ConnectionNotice、IdentityRecovery。

新增 UI 投影契约见 `../contracts/table-view.ts`；它只消费游戏公共快照与本人的私密数据，不替代 `types.ts` 的领域契约。

- 展示组件从view model接收数据，不直接读取服务端内部状态。
- LocalSentenceDraft管理本人排列、逗号和待提交选区；牌权、票数、倒计时期限、允许动作来自权威快照。
- `GameClientAdapter`暴露订阅快照、发送命令、恢复身份；提供同一接口的MockAdapter与SocketAdapter。
- mock仅用于开发预览和视觉状态测试。生产路由必须接SocketAdapter；界面“看起来能点”不计联机完成。
- 所有异步命令标出pending/ack/error，重复点击不能新建第二个actionId绕过去。
- 本地倒计时由服务端时钟偏移与phase.deadline.endsAt估算；归零只刷新状态/请求同步，不能在浏览器直接宣布流局或投票结果。
- 私密草稿保存采用可替换适配层，失败时不影响牌权。手牌变更后修剪非法草稿ID；重连快照覆盖旧牌权，再合并仍合法的本地排列。

## 10. 动效与反馈

摸牌：180ms轻移入；出牌：160ms移至中央；句子亮牌：220ms淡入放大。动效全部结束后界面仍与已提交状态一致；不会为了动画延迟处理服务器事件。减弱动态模式下用0—80ms淡入。

出牌后不播放长动画阻挡8秒响应。成功胡牌可有短促暖金描边与桌面轻亮，不覆盖句子。反对结果采用清晰文字与匿名标注，不羞辱某位玩家。

## 11. 字体、GPU、恢复与资源管理

### 11.1 汉字牌面

采用可控字体生成汉字 CanvasTexture/atlas，牌体保留上游厚度与灯光关系。输入是 `tileId→char`，同一个字可共享纹理，但实例身份不能合并。字体先等待 `document.fonts.ready` 或项目明确的 FontFace 加载结果；加载完成/回退时更新一次纹理 atlas，不能让空白/豆腐块成为已验收状态。需要覆盖实际字库 84 字及产品允许的扩展字。`ui-cjk-subset.woff` 仅服务本包示意图，不能当成任意汉字生产字体。

公开已弃字和胡牌句可以绘制字面；对手私密手牌和牌墙仅有背面占位，纹理 atlas 不得包含从服务端泄露的未知字符。字体/牌背/木纹资源按采用文档记录许可；不沿用上游英语字母序号、字母频次、通配牌图形。

### 11.2 渲染预算（目标，不是实测结果）

- 桌面交互目标 60 fps、手机目标至少 30 fps；在真实目标 Mac 与一台手机上记录设备、浏览器、分辨率、测量场景和中位/P95帧时。未跑标 `NOT_RUN`，不得把本包 PNG 当性能证据。
- 初始 DPR 上限桌面 2、手机 1.5；限制同时运行的全屏 OutlinePass，优先使用低成本的牌边高亮。先降后处理/阴影/装饰纹理，再降 DPR，不缩小汉字与命中目标。
- 保留 `OutputPass`/色彩空间正确性；关闭后处理时也要维持 sRGB 输出一致，不能出现“手机一降质桌布全黑”。
- 静止时按需渲染；动画/拖拽/相机改变时开帧循环。标签页后台暂停动画和音效，服务器快照及倒计时仍按权威时间恢复。
- 每次卸载释放 RAF、事件监听、ResizeObserver、controls、几何体、material、texture、render target、composer 和 renderer；共享材质/纹理按引用所有权释放。依照 UI30 完成挂载/卸载、3D/回退/重试共 20 次生命周期循环，再换房；预热后 canvas、活动 RAF 与 GPU 对象不应持续增长。

### 11.3 连接恢复和 WebGL 上下文丢失

重连先以服务端 current snapshot 与 controlEpoch 重建权威视图，再协调草稿中仍合法的 tileId。清空未提交或旧 epoch 的动画队列，不能从旧场景里推断“刚摸了一张”而再次发送 DRAW/出牌。

`webglcontextlost` 时保留网络会话与唯一草稿，展示同风格 DOM 回退和“正在恢复牌桌”；不重新登录、不新建房间、不延长服务器计时。恢复时按最新快照重建几何与资源，版本同步后才接回投影命中层。WebGL 重建失败也必须让用户通过 DOM 完成本回合操作。主动从后台回来需重算投影与倒计时，不能重放十几秒已过期动画。

## 12. Astra 交付与验收

至少提交：真实 Three.js 渲染入口、被采用的上游文件及修改说明、4 人基线对照、2/3/4/5/6 人布局、390/430/1440 视觉截图、字体纹理例、控制器与 DOM/3D互斥模式、全部主要状态 fixture、触摸/键盘验证、WebGL 回退与恢复、SocketAdapter接入点。图形性能和实时多人游戏分别验证。

重点验收：

1. 四人一眼可认出选定木边绿绒桌与奶白厚牌，而非退回原 V1.0 白蓝椭圆方案。
2. 2–6 座次映射完整正确，4/6 人同时显示的公私密信息均正确；不能写死 4、90°、108 张或 34 种牌。
3. 桌面默认 3D 手牌与其 DOM 命中层位置一致；相机/窗口变化不误选。整理模式和手机模式隐藏同批本人 3D 牌；只有一份草稿和一次命令。
4. 390 px 下 14 字和 3 逗号同时存在无水平溢出；行末逗号锚点和读屏顺序正确，中文字至少 28 px。
5. 反对按钮准确且完整；0–3 段异议可撤回、跨行、跨逗号，投票中的倾向与归属不泄漏。
6. 缓冲、AI、主动恢复、旧会话失效清楚区分；AI不吃不胡不投。
7. 客户端 scene、DOM、atlas、网络消息均无他人隐藏手牌/牌墙顺序/恢复码。
8. 失败/撤回自有14张申胡后30秒强制弃牌，无额外摸牌/重新申胡；借弃牌失败保持13张。
9. 字体迟加载、WebGL丢失、快速切房、快速恢复不造成空白牌、重复场景、悬空命令或本地改判。
10. 源码采用与资产来源明确；性能、联机、真实部署记录真实结果，不能把概念参考当已完成实现。

完整新增验收参照 [12-UI-ACCEPTANCE.md](12-UI-ACCEPTANCE.md)。
