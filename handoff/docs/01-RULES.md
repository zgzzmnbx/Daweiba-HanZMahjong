# 文字麻将 · 权威规则 V1.0.0

日期：2026-10-21（Asia/Hong_Kong）。状态：交付开发的基线；可调数值属于产品默认，不冒充已试玩平衡。本文是游戏语义的唯一权威来源。若接口、原型或示例与本文冲突，先修正它们；用户后续明确决定优先于本文。

## 1. 用户已确认的六项要求

U1：只允许吃上家刚打出的牌。接入手牌后，再打掉自己的一个字。

U2：玩家自己断句；界面最多提供三个可以拖拽的逗号，自由放入牌组。

U3：房间人数可选，2、3、4、5、6人均可完整游玩。

U4：投反对票时，可以圈选觉得不合理的词句；反对按钮准确使用“写的什么玩意”。

U5：掉线有缓冲，之后由简单AI接管，自动摸牌、打牌，永不胡牌。

U6：掉线成员可以再次登录，恢复自己的身份、座位和牌局。

## 2. 补齐并冻结的默认项

这些默认不代表用户逐项明确确认，但实施方可直接照此落地，不要停下来逐项追问。需要修改时记入决策记录并更新关联契约、测试和UI。

| 项目 | 默认值 |
|---|---|
| 每人常态手牌 | 13张；行动阶段14张 |
| 胡牌 | 14张全用，每个实体牌ID恰好使用一次 |
| 字牌 | 简体常用汉字；同字可以多张；无万能牌、无谐音代字 |
| 标点 | 仅0—3个中文逗号“，”；不占牌；不支持任意文本插字 |
| 行牌方向 | 稳定座位索引递增循环；UI可以旋转视角，不能改变逻辑顺序 |
| 吃牌次数 | 每人每局最多3次；仅上家最新弃牌 |
| 吃牌后禁打 | 本次不能立即打回刚接入的那张实体牌；同字的另一张可打 |
| 碰、杠 | 均不设 |
| 投票 | 申胡时其他在线真人构成冻结评审集合，严格过半赞成 |
| AI评审 | 不参与；不自动赞成，也不自动反对 |
| 回合思考 | 60秒；系统在正常摸牌回合开始时自动摸入第14张 |
| 弃牌响应窗 | 8秒；各人可以胡/过，下一家另可吃 |
| 借弃牌申胡后的排句 | 45秒 |
| 投票时间 | 45秒 |
| 自有牌申胡失败/撤回后弃牌 | 30秒，必须出牌，不能同机会重申 |
| 掉线缓冲 | 15秒，从服务端确认连接丢失开始计算 |
| AI动作延迟 | 800毫秒；服务端定时器，客户端不决定 |
| 全员离线 | 暂停并保存，保留24小时；无人回来则过期结束、不计分 |
| 计分 | 获胜者胜局数+1；失败、流局、终止不扣分 |
| 配牌 | 按人数用固定版本实验字库：2人120、3人144、4人168、5人192、6人216张 |

牌库规模按72+24N取值，只为提供可执行的实验起点。它尚未经过多人实玩验证，不得宣称胜率、局长或平衡性已经达标。

## 3. 房间、身份与席位

R-001：房主创建房间时设置2—6人的容量，本房间容量固定，想换人数则新建房间。每人首次入座可选空座，已入座首版不提供换座。必须全部座位被真人占用且全部准备后才能开始。AI仅作为本局真人掉线后的替身，不能用AI填空位开局。

R-002：开始时冻结座位顺序、人数、规则版本、字库版本。中途不能改变人数、换座、加入替代真人。已经在座的人可恢复身份；其他来访者显示“本局进行中”。首版不做观战。

R-003：逻辑座位为0..N-1。next(i)=(i+1)%N，previous(i)=(i-1+N)%N；对弃牌者i，唯一普通吃牌者是next(i)。两人局同样适用。

R-004：初始庄家由服务端随机选；后续每局按next轮庄，与上一局输赢无关。初始庄家14张，其余人13张，共发13N+1张。

R-005：身份由服务端签发的玩家凭据证明。昵称和房间码均不证明席位归属。同浏览器刷新自动恢复；换浏览器/设备可用首次入座提供的私密恢复码恢复，码仅保存哈希，不出现在公共房间状态和日志中。恢复码可重新生成，旧码随即失效。

R-006：同一席位只有一个有效控制会话；成功恢复后增加controlEpoch，撤销旧会话写权限。旧页面可以显示“已在其他设备恢复”，不能与新页面同时出牌。

R-007：房主只是组织者，无权替人投票或修改进行中的规则。房主掉线超过15秒时，房主身份交给座次最近的在线真人；若没人在线则暂不转移。房主身份变化不改变玩家座位和牌权。

## 4. 牌、私密排列、逗号

R-010：实体牌有唯一tileId和一个汉字char。同字不同tileId是不同牌。牌必须恰处于牌山、某人手牌或某个弃牌记录之一；胡牌候选、句子展示和批注只是对牌ID的引用，不能复制实体牌。

R-011：私人排句是手牌的排列视图。允许随时调整，不影响牌权和回合。摸牌不会自动重排已有字，新增牌置于末尾并高亮。若手牌改变，移除失效牌ID、保留剩余顺序，将新增牌补到末尾。

R-012：逗号只占两个字之间的间隙。13张草稿有12个间隙，14张候选有13个间隙。最多3个，不能放句首、句末，同一间隙不能重复放。逗号可以拖回托盘；不能通过逗号托盘加入句号、空字符或自由文本。

R-013：提交时用orderedTileIds和commaAfterTileIds表达句子：逗号锚定在某个非末尾牌ID之后。重排时逗号跟随其左字；若锚点变成末尾或该牌被移出，则逗号回托盘。键盘与触摸均须有等价操作，不能只支持鼠标拖拽。

R-013a：普通手牌草稿与借弃牌候选草稿分开保存。前者只能引用本人实际手牌，后者在HU_COMPOSE期间可引用本人13张和该候选的借用牌，并绑定当前来源与阶段。候选结束即清理候选草稿，不能把借用牌混入普通手牌草稿；两类草稿分别有私密版本号，重连按当前合法阶段恢复。

R-014：完整句意由真人判断；允许口语、夸张、荒诞、诗意及连贯短句。机器只验证14张用牌和逗号约束，不做语义判胜、不允许AI替用户生成申胡句子。

## 5. 摸牌、出牌、吃牌

R-020：普通回合开始，服务端从牌山摸一张，原13张变14张；庄家首回合和吃牌回合不额外摸牌。

R-021：14张行动阶段玩家可出牌，或提交自己的14字句子申请胡。出牌后回到13张，开启该张弃牌的8秒响应窗。直到响应流程结束之前不许下一家摸牌。

R-022：非弃牌者均可登记HU或PASS。只有next(discarder)可登记EAT，且本局吃牌次数<3。每人对该窗口只有一次最终意向，提交后不改；收到的不是最快抢到，优先级按规则决定。离线/AI席位在窗口建立时视为PASS。

R-023：窗口到期或所有可能响应者均提交时，冻结申请集合。HU优先；多个HU按从弃牌者下一家开始的座次顺序排队。不存在多人同时获胜；先获通过的一人结束本局。

R-024：没有HU，或所有排队HU都未成功时，执行原窗口已登记的EAT；兑现时接字者必须仍为在线HUMAN，否则取消EAT，从next(discarder)开始普通摸牌回合。不能看过前一人亮牌后补报HU/EAT；选择HU后失败的同一人也不能再改为吃。排队HU取出时同样重验身份：HUMAN进入排句，BOT撤回跳过，DISCONNECTED_GRACE只等原graceEndsAt剩余缓冲，不能重新给15秒。

R-025：吃牌把最新弃牌转移到接字者手牌，实体牌只移动一次；吃牌次数+1。接字者有14张并可排句申胡或出牌；本次出牌不能打回接入的实体牌。出牌后继续其下一家。上家限制意味着普通吃牌不会跳过座位。

R-026：在线玩家行动60秒未完成时，系统只代执行本次合法弃牌，之后仍保持真人模式；不永久切成掉线AI。出牌选择沿用简单AI策略，且遵守吃牌后禁打限制。此“本次超时代出”须单独提示，不伪装为掉线。

R-027：牌山用尽后仍处理当前弃牌的响应及其引发的合法动作。只有准备开始普通摸牌回合时已无牌可摸，才流局。每人最多3次吃牌保证不会无限接字。

## 6. 申胡、排句与投票

R-030：自有14张申胡必须在本人行动阶段提交完整排列和逗号，经形式校验后直接进入投票。不能让服务器因找不到词典中的句子而拒绝。

R-031：借最新弃牌申胡，先在8秒内登记HU意向，轮到本人的候选时进入45秒排句阶段。自己的13张加临时引用的弃牌组成14张，弃牌此时仍在原弃牌记录中，仅被预留，不能提前转成手牌。提交后进入投票。本人可在此排句阶段点击“放弃”，逾时未提交也撤回该候选，继续原排队流程；进入投票后不能主动撤回改句。

R-032：评审集合在每个候选正式进入投票时，冻结为“除申请人以外、该时刻在线且由真人控制的本局玩家ID”。令其人数为m，通过阈值T=floor(m/2)+1。m=0时不开始评审：自有14张申胡返回NO_HUMAN_REVIEWER错误，保留原行动时间；借弃牌候选无评审者时撤回并继续响应队列。

R-033：全员在线时：2人局1/1、3人局2/2、4人局2/3、5人局3/4、6人局3/5。应在房间规则说明中明确三人局需要两名对手都赞成。

R-034：每个评审最多提交一次APPROVE或REJECT。投票过程中只显示已投人数，不显示倾向、选区或投票者身份。所有评审提交或45秒到期后统一结算；m和T不因中途掉线而减少。

R-035：赞成票达到T则通过，否则不通过。未提交显示ABSTAIN（未投），不能记为反对。已冻结评审掉线后如果在截止前恢复原身份，可以投票；投票开始时不在集合内的人即使回来，也不能加入这一轮评审。AI不会代投。

R-036：反对按钮文案必须是“写的什么玩意”。反对者可在14字句子上选择0—3段不重叠的连续区间，也可以不选直接反对。索引从0到13，采用[start,endExclusive)。逗号不占字符索引，选区可以跨逗号。重复汉字按出现位置区分，不能用字符串查找代替索引。

R-037：赞成票不能带异议选区；反对选区必须在当前proposalId的冻结句子中有效。结算时展示总票数、阈值、弃权数及匿名合并的异议标注，不公开“谁反对谁”。对外历史不得包含评审者与立场的映射。

R-038：胡牌被否决：自有14张申请人必须弃一张，重新给30秒弃牌时间，同一14张机会不得再次申胡；借弃牌申请人仍为13张，继续原胡牌队列或原EAT申请。自有牌申请撤回也按同样30秒强制弃牌处理。申请失败不扣分，但已亮出的句子保留在本局公共历史。

R-039：胡牌通过时先固定胜者、牌来源和句子快照，再记一次胜局，进入ROUND_FINISHED。借弃牌胡不必为了结算把实体弃牌移动到胜者手牌；胜利证据记录引用即可。结算写入和胜局计数必须幂等。

## 7. 掉线、简单AI、重新登录

R-040：进行中的牌局，服务端确认连接丢失后，席位变为DISCONNECTED_GRACE，记录15秒截止时间，保留全部牌和身份。缓冲期内回来恢复HUMAN，不执行AI行动。候场/结算没有进行中的牌局时不启用AI，离线15秒后释放座位并清除准备状态，保留身份和历史胜局；回来可重新选空座，不冒领已被他人占用的座位。

R-041：若当前轮到该掉线玩家行动，等满缓冲期再由AI接管；该席位原60秒超时代出不得抢在15秒缓冲结束前发生。若掉线者当前不行动，其缓冲不暂停其他人的正常回合。

R-042：15秒仍未恢复则变为BOT。AI只做合法自动摸牌和弃牌；不吃、不申胡、不投票、不调用外部模型API。其策略只接收自己的手牌和公共信息，不接收他人手牌或未来牌山。可以优先弃重复字，再按字库连接权重弃较难用字，平局用可重放的随机源打破。

R-043：申胡排句或投票期间申请人掉线：在该候选结算前，候选的逾时/结算需让出最多15秒恢复缓冲。若在缓冲期内恢复则继续；否则撤回申请（不算语义否决、不计胜），再按原来源恢复牌局。原先投票作废，AI不能继承申请而获胜。该缓冲可能短暂冻结全桌，须有可见倒计时。

R-044：评审者掉线不冻结投票、不缩小分母；按照R-035处理。AI接管后也不代投。该默认优先保证本局继续推进。

R-045：恢复身份操作与AI动作进入同一个房间串行队列。恢复前AI已经成功提交的动作保留；恢复成功后撤销尚未提交的AI定时任务，增加controlEpoch。旧epoch的AI动作、旧客户端动作全部拒绝。不能回滚AI已经合法打出的牌。

R-046：恢复后下发本人可见的完整权威快照、私密排句草稿和当前截止时间。若此时本人仍处于可操作阶段，给予至少10秒操作时间；不能额外摸牌。已由AI结束的回合等正常轮到自己。

R-047：所有真人连接都离线时，立即冻结业务阶段计时，保存剩余时间，不让AI互打消耗牌山；掉线15秒计时和24小时保留计时仍走。任一原席位真人恢复后续局，其他离线且已过缓冲的席位可作为BOT继续。离线申请人的恢复缓冲到期撤回操作可记为恢复时优先处理的待办，不在全员离线时推进游戏。

R-048：服务重启时从持久化快照恢复为PAUSED_RECOVERY，废弃旧进程的定时器与连接标识。第一个原席位恢复后重建当前阶段期限（至少10秒），其余席位进入新的15秒恢复缓冲，随后可由BOT接管。已过全员离线24小时保留期的局只能显示过期结束。

R-049：任何恢复路径使用同一优先级：先检查24小时过期→处理已到期的申请人撤回待办→若无人在线保持暂停→若当前申胡申请人为BOT则撤回，若为DISCONNECTED_GRACE则保持PAUSED_CLAIMANT_GRACE至其已有截止→其余情况才RUNNING。因此非申请人先回来，不会提前结束申请人的剩余缓冲。重启新给的15秒只设一次；已有暂停保留期限不因重启顺延，若此前没有期限则首次恢复加载时设置并持久化。

## 8. 取消、结算、下一局

R-050：本局首次有效胡牌立即结束；其他排队候选取消。流局或进行中牌局全员离线过期均不计胜。已完成的WIN/DRAW/TERMINATED结果不可再被房间回收改成EXPIRED；候场/结算房间回收只关闭房间，保留已经记录的结果与胜局。

R-051：正常结束后保留句子、匿名异议、胜局记录和本局规则版本，清除所有准备标记。LOBBY和ROUND_FINISHED均允许真人加入空座、READY及房主START_ROUND；开始命令须检查满员、全部真人在线并准备，且closeAfterRound=false。新局原子生成新roundId、洗牌发牌、清理上一局活动牌区/候选/草稿并按固定方向轮庄，旧结果单独归档。不能让离线AI自动准备或连续开局。

R-052：候场或结算状态，房主可关闭房间。进行中房主只能设置“本局结束后关闭”，不能立即清掉其他人的对局。若只剩1名在线真人，该玩家可以点击“结束本局（不计分）”终止并保留记录；服务端在执行时重新检查在线真人数。首版不另做解散投票。普通离开页面只触发掉线接管，不删除席位。

## 9. 验收时不可放宽的原则

I-01：任意时刻实体牌唯一归属；候选引用不增加牌数。

I-02：只有当前控制会话、合法阶段、合法牌权的命令才能改变状态。

I-03：每次有效动作有唯一actionId；重试不会重复摸牌、重复弃牌、重复加分。

I-04：公共消息不包含他人暗牌、牌山未来顺序、恢复码、会话凭据或投票身份映射。

I-05：断线AI从不吃、从不申胡、从不投票，无法以自己控制的席位获胜。

I-06：UI支持全部2—6人数；上家以逻辑座次判断，不能看屏幕左右位置。

I-07：同一规则必须在文档、契约、状态机、UI提示和测试中一致；mock通过不等于多人联机验收通过。
