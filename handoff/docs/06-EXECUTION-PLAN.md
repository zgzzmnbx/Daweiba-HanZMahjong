# Astra / Sol 目标执行计划 · V1.1.0

## 1. 终局目标

交付一款可在Mac运行、可经火山云公网入口供好友浏览器访问的文字麻将。2—6人所有玩法走真实服务端；六项用户确认要求均能现场演示。当前交接包不声称已经完成这些实现。

UI采用用户已确定的EnglishMahjong-web牌桌，固定提交6830301df3061cdd25350cf56807473e5505b311。先建立真实WebGL四人视觉基线，再扩展汉字/人数/投票；不得一边重写全部视觉一边推测源项目效果。旧白蓝椭圆桌要求在V1.1.0中已被替换。

建议仓库结构：

```text
apps/web/                 React界面、交互、客户端adapter
apps/web/src/table3d/     按固定上游采用并改造的Three.js渲染层
apps/web/src/table-ui/    DOM排句/投票层与唯一交互控制器
apps/server/              Socket.IO、HTTP身份入口、房间队列、SQLite、定时器
packages/engine/          无网络无DOM的规则引擎与纯函数
packages/contracts/       共享类型与运行时schema
packages/deck/            固定字库与版本
tests/engine/             规则、牌数、状态与时钟测试
tests/integration/        多客户端、身份、持久化、重连与竞态
tests/e2e/                浏览器全链路与视口检查
docs/                     决策、部署、验收、交接
handoff/                  本交接包的只读基线
```

## 2. 任务划分与验收门

| 阶段 | 负责人 | 必须产出 | 完成条件 |
|---|---|---|---|

| M0-V 真实3D视觉基线 | Astra | 四人Three.js场景、合成可见数据、原图区域对照、运行截图 | 木边绿绒桌/奶白厚牌/相机比例成立；非背景图/iframe；来源可追溯 |

| M2 规则引擎 | Sol | 纯引擎、字库、可注入时钟与随机源、规则测试 | 2—6人数循环、14张、吃上家、投票/候选续行、牌数守恒通过 |
| M3 服务与恢复 | Sol | 房间串行队列、身份、Socket.IO、事务存档、AI与恢复 | 两个以上独立客户端；重复动作、AI竞态、进程重启无重复结算 |
| M4 3D界面接真数据 | Sol | SocketAdapter、TableViewAdapter、权限、动画generation与恢复 | 无双命令/旧动画，WebGL失败保局；默认入口接服务，投票索引正确 |
| M5 全链路与UI验收 | Sol，Astra审阅 | 原91条+docs/12结果、全人数实机证据、视觉对照/性能/资源记录 | 2/3/4/5/6人完整端到端，正常3D与故障回退都验证；P0/P1修复 |
| M6 部署准备 | Sol | Mac运行脚本、配置样例、备份恢复、云入口操作手册 | 本地生产构建可运行，healthz/readyz有效；未具备外部环境如实标记 |

并行方式：M0先冻结contracts；之后Astra做M1时，Sol可以按同一契约做M2/M3。M4开始前合并契约和UI状态清单。不要两个模型同时改同一个组件、类型定义或规则文件。

M0-V是视觉采用门，M1交接前必须完成；它不阻止Sol并行做纯引擎。Astra无需等待未公开的原站Python后端，可直接用本地合成快照驱动所采用渲染器。若上游模型资产来源待确认，按docs/11程序几何替代方案完成真实3D基线，不能把整个任务停在许可询问。

## 3. 文件责任边界

- Astra拥有设计token、布局、页面组件、文案、操作反馈、可访问性和UI状态清单。
- Astra另外拥有上游renderer提取、相机/座位布局/材质、源文件映射和正常3D视觉基线；Sol拥有其真实快照/命令连接和并发正确性。双方共用table-view契约。
- Sol拥有engine/server/contracts实现、数据持久化、实时通信、身份恢复、AI以及自动化验证。
- Sol可以修改web中的adapter、hooks和事件绑定，也可修复与正确性直接相关的界面问题；不顺手重做已经验收的视觉风格。
- 跨边界变更必须记录原因、接口变化和受影响测试。契约变化先同步类型、fixture、UI mock、real adapter，再继续实现。

## 5. 验证策略

先固定夹具和规则断言，再实现纯引擎。集成测试使用可控制时钟模拟8秒/15秒/45秒边界，不靠真实等待碰运气。端到端使用隔离browser context模拟多个真人，禁止同一登录凭据开六个标签页冒充六个人。

必要层次：类型检查→规则/属性测试→服务集成→浏览器全链路→人工视觉检查。关键属性包括牌权唯一、抽牌总量、旧epoch失效和私密信息不外泄。AI/重连与消息重试需要交错次序测试；逗号与文本圈选需要触摸和键盘验证。

不要通过删测试、跳断言、扩大超时或改预期来让错误实现变绿。也不要无限重复同一测试。遇到失败先记录具体反例、定位状态转换和最小修复；连续三轮同类失败应重审假设、收敛问题，继续完成不受影响的工作。

所有证据标注 `PASS / FAIL / NOT_RUN / NOT_RUN_ENV_REQUIRED`。截图只证明看到的界面；不能代替引擎测试。契约检查通过也不代表游戏已经实现。

## 6. 必须持续执行的范围

普通实现决策按本包默认推进，无需用户逐项确认。依赖安装、代码编辑、局部修复、测试、文档完善均继续做。只有必要的外部凭据/域名/真实主机权限缺失，或用户明确修改核心规则时，才列出具体阻塞及影响；不要以此停止整个本地开发。

遵守当前运行环境的权限与审批。不要读取其他项目凭据、覆盖现有frp/Caddy配置、创建未经要求的公开站点，或绕过自动审批。真实部署前先生成可审阅的配置差异并按已获得授权执行。

## 7. 最终交付清单

可运行源代码、锁定依赖、启动说明、.env.example、规则与字库版本、上游采用版本/文件映射/许可、真实3D对照图、两份验收结果、已知限制、Mac启动/关闭/升级、备份恢复、云入口模板及真实部署状态。用户应能照README开起来，知道哪些已验证、哪些待现场环境。
