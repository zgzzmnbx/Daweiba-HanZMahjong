# 给 Astra 的启动提示词 · V1.1.0

在 Codex 中选择实际可用的 Astra，将分隔线后的正文粘贴到目标模式。

---

请在当前独立项目中按 handoff/ 的完整交接包实现“文字麻将”的规划与 UI，并给 Sol 留下可直接接入逻辑的接口和证据。若解压目录名称不同，先定位 README 与 docs/01-RULES.md。

用户已经确定采用 https://englishmahjong.com 的牌桌 UI，上游仓库为 https://github.com/Bruce-pac/EnglishMahjong-web ，固定提交 6830301df3061cdd25350cf56807473e5505b311。这个选择覆盖旧版浅色白蓝椭圆桌方案。保留深棕环境、木边绿绒牌桌、奶白厚牌、围坐视角和选牌反馈；正常设备必须是可运行的 Three.js 场景。采用其真实 renderer 并按文字麻将改造，不能仅画一张相似背景、把网页嵌进 iframe、或重新选择视觉风格。

游戏仍是2—6名好友真人联机：13+1汉字组成意思，人工投票胡牌；只吃上家刚打出的牌；最多三个可拖拽逗号；反对可圈选词句，按钮“写的什么玩意”；掉线15秒后简单AI只摸牌打牌，永不胡/吃/投票；可重新登录恢复。完整规则只从本包读取，不从上游英文麻将推断。

连续执行以下步骤，不停在方案描述：

1. 检查当前仓库、已有指令、用户未提交改动和运行环境。保留可用引擎与测试；若已使用 V1.0.0，按 docs/13-V1.0-UPGRADE.md 增量升级。不要修改其他业务仓库。
2. 读 README、docs/01—03、06—08、11—13、contracts/types.ts、table-view.ts、rules.defaults.json，以及 references/englishmahjong/ 的来源、许可和固定源码。规则、视觉、显示 adapter 各有权威，不照搬上游英文规则或四人常量。
3. 建立 docs/TASKBOARD.md、HANDOFF.md、DECISIONS.md、VERIFICATION.md、UI-ADOPTION.md。UI-ADOPTION逐项记录上游文件/函数、原提交、目标文件、保留与重写内容、许可和截图证据。
4. 先完成M0-V：在开发专用入口运行真实Three.js四人牌桌视觉基线，使用合成数据、程序牌体和汉字贴图；保持原绿绒桌、木边、相机、光照、奶白牌比例，逐区域对照包内原作者截图。原站后端未开源不阻塞此步骤，不连接其API。记录真实截图和命令。
5. 按docs/11逐文件清单提取src/table3d渲染部分。重写固定四人/90度座次、108容量、英文字母图集和旧状态协议；适配2—6人、120—216字库与视觉余量。未核实许可的人物和贴图用中性头像及程序几何替代，保留牌桌风格。
6. 建立单一TableViewAdapter与SentenceRackController。桌面默认真3D本人手牌+投影DOM命中/辅助操作层；展开整理句子时隐藏对应3D本人牌；手机竖屏为3D桌+DOM手牌。模式共用唯一orderedTileIds/commaAfterTileIds草稿。mesh不直接发命令，每张牌以tileId识别。相机移动时投影命中区域同步，不能点到邻牌。
7. 完成首页、好友房入座/准备、2—6人桌面、私密排句、三个逗号、借弃牌13+1候选、投票圈词、掉线/AI/恢复/结算。逗号和圈选必须可操作。390/430手机竖屏的7+7字牌与三个逗号不溢出；不强制横屏。键盘和触摸有等价操作。
8. 加入字体加载后的汉字纹理重建、WebGL context丢失后的同状态2D回退及恢复3D入口、资源释放和低画质档。不能把回退模式当正常设备默认完成态。相机不抢排字/圈词手势，对手暗牌不能仅以背面遮挡隐藏纹理。
9. 执行docs/12中可验证部分，保存同视口对照图、全人数布局和手机/键盘交互证据。帧率记录设备/浏览器/DPR与方法，不将目标写成实测。mock明确标记开发用途。
10. 更新HANDOFF：固定上游与项目commit、源码采用清单、组件/adapter、已操作状态、待Sol接线项、命令、缺陷、证据和下一任务。环境若支持Sol委派可按边界交接，否则留接棒记录，不虚构已经切换。

你负责规划、真实3D界面和交互；引擎、服务、数据库和权限由Sol按同一契约实现。例行本地实现不必逐项询问。没有域名/云机时继续完成UI与本地交接，不停在设计图。

结束报告修改、运行方式、源码采用依据、真实验证与仍属mock的范围，给出HANDOFF路径。结论必须与证据一致。
