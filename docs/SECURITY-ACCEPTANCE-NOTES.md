# 联机与恢复的补充验证重点

本文件是依据任务书整理的验收提示，不声明任何场景已经通过。

1. Cookie 使用游戏专有名称。多个服务共用公网IP但端口不同，Cookie不按端口隔离；不记录完整Cookie/请求头，不复用其他服务会话；写操作和Socket握手必须严格校验PUBLIC_ORIGIN。
2. 非成员请求roomId不能获得公共牌局/私密手牌（首版无观战）；旧会话恢复后应撤销订阅并清除私密缓存。
3. 恢复码经POST请求体、只存高熵码的hash；无URL/query、日志、公共快照副本；轮换后旧码失效，错误尝试限流。
4. 同一个actionId的不同命令载荷应拒绝，合法重复返回原应答；持久化覆盖restart与广播丢失。
5. 对并发VOTE/RESPOND只用phase、对象ID与一次性资格门控，不能被首个票增加全局stateVersion误拒。
6. 换设备恢复与已排队AI共用串行提交，恢复优先/AI优先两种次序均测；旧epoch客户端和AI都不得再写。
7. 开发夹具入口、固定种子、测试时钟控制接口不进入公网生产功能。浏览器不得获取完整RoomAggregate。
8. 多设备验证必须隔离Cookie上下文，不能一个session开多页冒充不同玩家。生产验收使用独立测试房间和明确昵称，不影响真实用户房间。
